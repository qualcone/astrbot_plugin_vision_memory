# astrbot_plugin_vision_memory

为 AstrBot 提供图片识别，并把核实过的角色信息写入 [LivingMemory](https://github.com/lxfight-s-Astrbot-Plugins/astrbot_plugin_livingmemory) 长期记忆。

## 做什么

用户发来一张图（动漫、游戏角色、表情包等）时：

```
图片
 │
 ├─ 1. Google Cloud Vision 以图搜图：找到网上含这张图的网页
 │
 ├─ 2. Gemini 打开这些网页，读内容，判断是哪部作品；
 │     认出作品但认不准角色时，再联网搜索这部作品的角色列表，按外貌逐个比对出角色
 │
 └─ 3. 把“识别结论 + 依据网页”交给主模型回复
        └─ 核实无误后，主模型调用 save_character_memory 写入 LivingMemory，之后不必重复查询
```

为什么这样做：只靠模型看图后再用文字搜索，遇到外貌相似、画风不同的角色很容易认错。先用图片本身反查，再让模型读真实网页，结论有依据，错了也能顺着链接核对。

## 运行要求

- AstrBot ≥ 4.24.2
- 已安装并配置 LivingMemory
- Google Cloud Vision API Key（用于以图搜图）
- Gemini API Key（用于读取网页并判断）

## 配置

菜单按处理顺序排列。没有单独的“总开关”：整个插件的启停用 AstrBot 自带的插件开关；**①、② 的两个密钥都填好，图片识别才会工作**，缺任一个时图片会原样传给主模型，不影响聊天。

| 分组 | 配置项 | 说明 |
| --- | --- | --- |
| ① 第一步：Google 以图搜图 | Google Cloud Vision API Key | 见下文“获取 Vision Key”。 |
| | 网络代理（可选） | 访问 Google 需要代理时填写。 |
| ② 第二步：Gemini 读取网页 | Gemini API Key | 在 Google AI Studio 创建。 |
| | 模型 | 需支持图片输入和读取网页（URL Context），默认 `gemini-3.5-flash`。 |
| | 接口地址 | 默认官方地址；使用反向代理时改成代理地址，密钥会发往该地址。 |
| | 网络代理（可选） | 访问 Gemini 需要代理时填写。 |
| ③ 第三步：给主模型的提示 | 行为指引内容 | 识别图片后追加到主模型系统提示词末尾的一小段话；清空则不追加。 |
| ④ 长期记忆 | 外部 API 地址 / Key / 记忆范围 | 见下文“LivingMemory 设置”。 |
| ⑤ 调试 | 调试模式 | 日志输出完整过程，见下文“调试”。 |

### 获取 Vision Key

1. 在 [Google Cloud 控制台](https://console.cloud.google.com/projectselector2/home/dashboard) 创建（或选择）项目，并关联结算账号。
2. [启用 Vision API](https://console.cloud.google.com/apis/enableflow?apiid=vision.googleapis.com)。
3. 在 [凭据页面](https://console.cloud.google.com/apis/credentials) 创建 API 密钥（以 `AIza` 开头），建议在“API 限制”里只勾选 Cloud Vision API。

计费：Web Detection 每月前 1000 次免费，之后约 3.5 美元 / 千次（以 Google 官方价格页为准）。每张图计一次。

### LivingMemory 设置

1. 在 LivingMemory 中启用 `external_api.enabled`（默认监听 `127.0.0.1:7801`）。
2. 用 `/lmem apikey` 创建同时具备 **read** 和 **write** 权限的 Key，填入“外部 API Key”。
3. 若 LivingMemory 的 `memory_scope_mode` 为 `global`，把“写入的记忆范围”设为 `global`，否则保持 `session`。

## 识别结果的处理

| 情况 | 给主模型的内容 | 原图 |
| --- | --- | --- |
| 给出了结论 | “作品 / 角色 / 其他可能 / 依据”（附可信度）和前 3 个依据网页链接 | 移除（避免主模型再凭印象猜） |
| 作品和角色都无法确认 | 该结论 | 保留，主模型仍可自己看图 |
| 网上没找到相关网页 | “以图搜图没有找到相关网页，无法确认” | 保留 |
| Vision / Gemini 失败或超时 | 已找到的网页信息（如有）和失败说明 | 保留 |

一条消息最多识别前 3 张图，其余原样保留。图片超过 7 MB 会跳过。

## 记忆的创建与更新

模型核实后调用 `save_character_memory`，插件通过 LivingMemory 外部 API 写入，附带当前会话的 persona 与 scope，完全相同的内容重复保存不会重复写入。

LivingMemory 外部 API 没有“修改”接口，更新按“写入新版本、归档旧版本”实现，保证同一角色只有一条有效记录：

1. 保存前，按角色名和作品名检索已有记忆。
2. 内容一致：不写入。内容不同（例如原先模糊）：先写入新版本，成功后再归档旧版本（可在 LivingMemory 中恢复）。
3. 没有已有记录：新增。

**只归档确认是本插件写入的记录**：该 ID 必须在本插件自己的登记表里，且 LivingMemory 返回它是有效状态、来源为外部 API、包含本插件写入的 `角色名：…` 与 `作品：…` 条目。LivingMemory 自己生成的记忆、其他客户端写入的记忆、手动创建的记忆，即使相似也不会被修改。登记表读取失败或丢失时，宁可新增一条也不会归档任何记录。

## 调试

开启“调试模式”后，在 AstrBot 日志中搜索 `[vision_memory][debug]`：

- Google 找到了哪些网页和实体；
- Gemini 读取了哪些链接及每个链接的读取状态（成功 / 失败）、Gemini 的原始输出；
- 最终发给主模型的内容、可用工具；
- 保存记忆时的参数、请求体和响应。

密钥不会输出，但日志会包含图片识别结果、对话文字和人设片段，排查完请关闭。插件加载时无论是否开启调试，都会输出一行“已加载：…”，列出各项密钥是否已填，并在缺少密钥时警告。

## 隐私与安全

- 图片会上传到 Google（Cloud Vision 和 Gemini）。若使用免费额度，服务商可能将数据用于产品改进，请自行评估。
- 密钥以保密字段存储，只放在请求头里发给对应服务，不写入日志，请求不跟随重定向。
- 识别结果附带声明，说明其中的文字只是图片或网页内容、不是对模型的指令。该措施只能降低提示词注入的风险，不能杜绝；网页内容也可能含有错误信息。
- 记忆由模型写入，搜索结果中的错误信息也可能被写入。工具对名称、作品名和描述做了长度限制。发现错误记忆时，可在 LivingMemory 中使用 `/lmem forget <id>`（管理员）删除。

## 调用量与费用

每条带图片的消息，每张图最多（最多处理 3 张）会产生：Google Vision 1 次；Gemini 1 次（读网页），认出作品但认不准角色时再 1 次（联网搜索角色列表）。为避免无谓消耗：

- 没有图片的消息不会触发任何调用；只对主模型追加一小段行为指引（约 100 多个 token）。
- GIF 动图（多半是表情包）直接跳过，不调用任何接口。
- 同一张图一小时内再次发送，直接复用上次的识别结果。
- 作品和角色一次就认出来时，不会发起第二次 Gemini 调用。
- 识别结果的完整文字只作为**本次请求的临时内容**发给主模型，不会存进聊天历史，因此不会在之后每一轮对话里重复发送；历史里只留一小段标记，例如 `[识别：夏目藍（中） / Sakura no Uta（高）]`，既保留了名字、方便追问，也让 LivingMemory 能按名字召回记忆。完整文字限制在约 700 字以内。
- 只把前 4 个网页交给 Gemini 阅读；网页正文由 Gemini 读取，会计入 Gemini 的输入用量。
- Gemini 的思考和 Google 搜索可能另行计费，请以 Google 官方价格页为准。

## 已知限制

- 以图搜图只对“网上已有的图”有效；新图、私人图、被裁剪或加滤镜过的图可能找不到网页。
- 有些网站（需要登录、仅 JS 渲染）Gemini 打开后读不到内容，此时只能依据标题和实体判断。
- 网页本身可能写错或张冠李戴，所以结论附有依据网页，便于核对。
- 写入的记忆能否被召回，取决于 LivingMemory 的范围与人格过滤设置，以及它的嵌入模型是否工作正常。
- 角色名需前后一致才会被识别为同一角色（“灵梦”与“博丽灵梦”是两条记录）。
- 升级提示：AstrBot 加载配置时会删除新配置结构里不存在的旧项。v0.7.x 保留了仍在使用的设置（各密钥、LivingMemory 设置），已删除的旧功能和开关的设置会消失；“行为指引内容”改用新的配置项，默认值已更新。
