# astrbot_plugin_vision_memory

为 AstrBot 提供图片识别，并把核实过的角色信息写入 [LivingMemory](https://github.com/lxfight-s-Astrbot-Plugins/astrbot_plugin_livingmemory) 长期记忆。

## 做什么

用户发来一张图（动漫、游戏角色、表情包等）时：

```
图片
 │
 ├─ 1. 识别来源（两个都是可选项，各有独立开关，同时进行）
 │      A. Google Cloud Vision 以图搜图：找到网上含这张图的网页
 │      B. 自带联网搜索的大模型 API（通义千问等）：直接凭图片联网识别；
 │         Google 找不到网页的二次元角色主要靠它
 │
 ├─ 2. （A 找到网页时）模型读这些网页，判断对象是谁（角色、真人、表情包等）和出处
 │
 ├─ 3. 再联网搜索这个对象的资料（外貌设定、身份、人设），并对照图片核对
 │      （只认出作品时，改为搜索该作品的角色列表，按外貌比对出角色）
 │
 └─ 4. 合并 A、B 的结果，把“识别结论（对象、出处、设定）+ 依据网页”交给主模型回复
        └─ 核实无误后，主模型调用 save_character_memory 写入 LivingMemory，之后不必重复查询
```

第 2 步“读取网页并判断”可以选 Gemini，也可以选 AstrBot 里配置的任意模型；第 3 步联网搜索资料由 Gemini 完成。

为什么这样做：只靠模型看图后再用文字搜索，遇到外貌相似、画风不同的角色很容易认错。先用图片本身反查，再让模型读真实网页，结论有依据，错了也能顺着链接核对。

## 运行要求

- AstrBot ≥ 4.24.2
- 已安装并配置 LivingMemory
- **至少配好一个第一步来源**：
  - A. Google Cloud Vision API Key，加上第 2 步读取网页的模型（Gemini API Key 推荐，或 AstrBot 里已配置的任意对话模型）；
  - B. 任一家自带联网搜索的大模型 API（通义千问、智谱、豆包、OpenAI 等）。
  两个都配好效果最好，也都可以单独使用。

## 配置

菜单按处理顺序排列。没有整体的“总开关”：整个插件的启停用 AstrBot 自带的插件开关。第一步的两个来源各有**独立的开关**（默认开），**至少启用并配好一个**，图片识别才会工作；都没配好时图片会原样传给主模型，不影响聊天。

| 分组 | 配置项 | 说明 |
| --- | --- | --- |
| ① 第一步 · 可选 A：Google 以图搜图 | 启用 Google 以图搜图（开关） | 关闭后不调用 Google（密钥保留）。 |
| | Google Cloud Vision API Key | 见下文“获取 Vision Key”。要靠 A 单独识别，还需要在第 2 步配好读取网页的模型；没配时，只要 B 可用，Google 仍会被调用，用来交叉验证 B 的答案。 |
| | 网络代理（可选） | 访问 Google 需要代理时填写。 |
| ① 第一步 · 可选 B：联网大模型 | 启用联网大模型（开关） | 关闭后不调用这个模型（配置保留）。 |
| | 接口格式 / 接口地址 / API Key / 模型 | 三项“接口地址、Key、模型”都填好才工作。见下文“第一步 B：联网大模型”。 |
| | 额外请求参数（JSON） | 用来打开该厂商的联网搜索，原样合并进请求体。 |
| | 超时（秒） | 等待回答的总时长，默认 180。超时时会写出超时前收到了多少数据。 |
| | 核实提示词 | 发给该模型的指令，可修改，清空用内置默认。 |
| ② 第二步：读取网页并判断 | 读取网页的方式 | `Gemini 直连`（推荐）或 `AstrBot 里的模型`，见下文。 |
| | AstrBot 提供商 | 仅“AstrBot 里的模型”方式使用，选一个已配置的对话模型。 |
| | Gemini API Key / 模型 / 接口地址 / 网络代理 | 仅 Gemini 方式使用。Key 在 Google AI Studio 创建；模型需支持图片输入和读取网页（URL Context），默认 `gemini-3.5-flash`。 |
| ③ 第三步：联网搜索资料 | 联网搜索资料（开关，默认开） | 认出对象后再联网搜索它的外貌设定和人设；仅 Gemini 直连方式支持。关闭则只用第二步读到的信息。 |
| | 搜索资料的提示词 | 发给 Gemini 的指令，可修改，清空用内置默认。 |
| ④ 第四步：给主模型的提示 | 行为指引内容 | 识别图片后追加到主模型系统提示词末尾的一小段话；清空则不追加。 |
| ⑤ 长期记忆 | 外部 API 地址 / Key / 记忆范围 | 见下文“LivingMemory 设置”。 |
| ⑥ 调试 | 调试模式 | 日志输出完整过程，见下文“调试”。 |

### 第二步用哪个模型

| 方式 | 谁读网页 | 能力 |
| --- | --- | --- |
| Gemini 直连（推荐） | Gemini 自己打开网页（URL Context） | 认出作品但认不准角色时，会再联网搜索这部作品的角色列表，按外貌匹配出角色 |
| AstrBot 里的模型 | 插件抓取网页文字（标题、描述、正文摘录）后交给你选的模型 | 不做第 3 步（联网搜索资料、匹配角色）；模型不支持图片输入时自动只用文字判断 |

插件抓取网页时只访问公网地址：拒绝本机、内网和链路本地地址（重定向的目标同样检查），限制页面大小和超时，不携带任何凭据。需要登录或仅靠 JS 渲染的网站读不到内容，会在给模型的文字里标明“读取失败”。

### 第一步 B：联网大模型

Google 的网页匹配对一部分二次元角色搜不到。B 来源调一个**自带联网搜索**的大模型 API，让它直接凭图片联网识别。它与 A（Google）**互相独立、同时进行**，不会拿到 Google 的线索，所以两边的结论可以互相对照。合并规则：

- A 没认出来、B 认出来了：采用 B 的结果。
- 两边认出的是同一个：补充缺的出处和设定，依据里追加“联网大模型：…”。
- 两边认出的不是同一个：保留 A（经第 2、3 步核实）的结果，把 B 的答案列在“其他可能”里（“联网大模型认为 …”），由主模型向用户说明不确定。
- **A 完全没找到网页时**（或没启用），只要 B 可用，就只用 B 的结果，不需要 Gemini。
- B 失败、超时或没按格式回答，不影响 A 的结果。
- **没有第 2 步的模型、只有 B 时**：如果启用了 A 并填了密钥，Google 仍会被调用。B 的答案里的名字如果也出现在 Google 的网页标题或实体里，会在依据里写明“Google 以图搜图的网页或实体里也出现了这个名字”，并附上依据网页；没出现不代表错（Google 的结果多为英文名，B 常给中文名），不会因此否定 B。

各家的写法不同，所以做成了通用接口：

| 配置 | 说明 |
| --- | --- |
| 接口格式 | `chat`：POST `{接口地址}/chat/completions`（多数厂商）；`responses`：POST `{接口地址}/responses`（OpenAI、豆包、通义等） |
| 接口地址 / Key / 模型 | 按厂商文档填。模型需要支持图片输入并能联网搜索。 |
| 额外请求参数 | 一个 JSON 对象，原样合并进请求体（不能覆盖 model、messages、input），用来打开联网搜索；需要流式输出的厂商加 `"stream": true`，插件会自动读取流式结果。 |

**怎么测**（不受“启用联网大模型”开关影响，所以可以先测好再打开）：管理员在聊天里发 `/vmtest`，并在**同一条消息里带上一张图片**（或回复一条带图片的消息再发 `/vmtest`）。插件只调用这个联网大模型，不经过其他步骤，直接把模型的原始回答、插件能读到的字段，或者具体的报错发回聊天。只有 AstrBot 管理员能用，因为它会产生接口费用。

下面是各家常见的联网写法，**仅供参考，请以厂商最新文档为准，我没有逐家实测**：

| 厂商 | 接口格式 | 接口地址 | 额外请求参数示例 |
| --- | --- | --- | --- |
| 通义千问（百炼）**推荐** | `dashscope` | `https://dashscope.aliyuncs.com` | `{"enable_search": true, "search_options": {"search_strategy": "max", "forced_search": true}, "stream": true}` |
| 通义千问（备选） | `responses` | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `{"tools": [{"type": "web_search"}]}` |
| 智谱 GLM | `chat` | 厂商文档 | `{"tools": [{"type": "web_search", "web_search": {"enable": true}}]}` |
| OpenAI / 豆包（方舟） | `responses` | 厂商文档 | `{"tools": [{"type": "web_search"}]}` |

**通义千问（百炼）怎么配**（依据官方联网搜索文档 help.aliyun.com/zh/model-studio/web-search 和 Responses 兼容文档）：

- **图片加联网搜索，文档给的是 DashScope 原生多模态接口**：文档明确写多模态模型必须走多模态接口，并且开启联网搜索时必须流式（非流式报 `Non-streaming mode does not support Web Search`）。所以推荐 `dashscope` 格式，额外参数里写 `"stream": true`；`enable_search`、`search_options` 都放在请求的 `parameters` 里（插件自动处理）。
- 文档里所有 OpenAI 兼容 Chat Completions 的联网示例都是纯文字，**没有图片加联网搜索的示例**，所以 `chat` 格式没有文档依据。实测用 `chat` 格式时，`qwen3.8-flash` 曾把“要搜索”的工具调用当成文字原样返回（`<tool_call>…`），文档里没有解释这种现象；插件遇到会直接报错。
- **qwen3.8-flash 的搜索策略**：`turbo`（默认）和 `max` 可用，**`agent` 不可用**。`qwen3.8-omni-flash` 相反，**只能用 `agent`**。`qwen3.7-plus`、`qwen3.5-plus` 三种都可用。`forced_search: true` 表示每次强制搜索，`dashscope` 和 `chat` 格式支持，`responses` 格式不支持。
- `responses` 格式：文档写明 Qwen3.8 Flash 等模型通过 `web_search` 工具由模型自主多次搜索，`search_strategy` 会被**静默忽略**；不支持 `thinking_budget`，思考强度用 `reasoning.effort`。该格式下传 base64 图片是否被接受，文档没写。
- 思考：文档说联网搜索在思考和非思考模式下都支持。默认思考可能很慢、很贵（实测一次识图 6600 个输出 token，6400 个是思考）。可以在额外参数里加 `"enable_thinking": false` 对比耗时；`dashscope` 格式下同样放进额外参数。
- 计费：联网搜索按次收费，`turbo` 每 1000 次 3 元，`max`、`agent` 4 元（北京，文档摘要里的数字，以控制台为准），模型 token 另算，文档说明没有免费额度。
- 兼容接口不返回搜索来源，插件只读取模型最终的文字回答。

注意：图片会发往你填写的接口地址；联网搜索通常按次另外计费；各家的搜索来源信息不一定返回，插件只读取模型最终的文字回答。

### 获取 Vision Key

1. 在 [Google Cloud 控制台](https://console.cloud.google.com/projectselector2/home/dashboard) 创建（或选择）项目，并关联结算账号。
2. [启用 Vision API](https://console.cloud.google.com/apis/enableflow?apiid=vision.googleapis.com)。
3. 在 [凭据页面](https://console.cloud.google.com/apis/credentials) 创建 API 密钥（以 `AIza` 开头），建议在“API 限制”里只勾选 Cloud Vision API。

计费：Web Detection 每月前 1000 次免费，之后约 3.5 美元 / 千次（以 Google 官方价格页为准）。每张图计一次。

### LivingMemory 设置

1. 在 LivingMemory 中启用 `external_api.enabled`（默认监听 `127.0.0.1:7801`）。
2. 用 `/lmem apikey` 创建同时具备 **read** 和 **write** 权限的 Key，填入“外部 API Key”。
3. 若 LivingMemory 的 `memory_scope_mode` 为 `global`，把“写入的记忆范围”设为 `global`，否则保持 `session`。

## 识别结果的处理

| 情况 | 给主模型的内容 | 原图 |
| --- | --- | --- |
| 给出了结论 | “对象 / 出处 / 设定 / 其他可能 / 依据”（附可信度）和前 2 个依据网页链接；“设定”是联网查到的外貌和人设资料，主模型描述时以它为准 | 移除（避免主模型再凭印象猜） |
| 对象和出处都无法确认 | 该结论 | 保留，主模型仍可自己看图 |
| 网上没找到相关网页 | “以图搜图没有找到相关网页，无法确认” | 保留 |
| Vision / Gemini 失败或超时 | 已找到的网页信息（如有）和失败说明 | 保留 |

一条消息最多识别前 3 张图，其余原样保留。图片超过 7 MB 会跳过。

## 记忆的创建与更新

模型核实后调用 `save_character_memory`，插件通过 LivingMemory 外部 API 写入，附带当前会话的 persona 与 scope，完全相同的内容重复保存不会重复写入。

LivingMemory 外部 API 没有“修改”接口，更新按“写入新版本、归档旧版本”实现，保证同一角色只有一条有效记录：

1. 保存前，按角色名和作品名检索已有记忆。
2. 内容一致：不写入。内容不同（例如原先模糊）：先写入新版本，成功后再归档旧版本（可在 LivingMemory 中恢复）。
3. 没有已有记录：新增。

**只归档确认是本插件写入的记录**：该 ID 必须在本插件自己的登记表里，且 LivingMemory 返回它是有效状态、来源为外部 API、包含本插件写入的 `角色名：…` 与 `作品：…` 条目。LivingMemory 自己生成的记忆、其他客户端写入的记忆、手动创建的记忆，即使相似也不会被修改。登记表读取失败或丢失时，宁可新增一条也不会归档任何记录。

## 调试

开启“调试模式”后，在 AstrBot 日志中搜索 `[vision_memory][debug]`：

- Google 找到了哪些网页和实体；
- Gemini 读取了哪些链接及每个链接的读取状态（成功 / 失败）、Gemini 的原始输出；
- 最终发给主模型的内容、可用工具；
- 保存记忆时的参数、请求体和响应。

密钥不会输出，但日志会包含图片识别结果、对话文字和人设片段，排查完请关闭。插件加载时无论是否开启调试，都会输出一行“已加载：…”，列出各项密钥是否已填，并在缺少密钥时警告。

## 隐私与安全

- 图片会上传到 Google（Cloud Vision 和 Gemini）。若使用免费额度，服务商可能将数据用于产品改进，请自行评估。
- 密钥以保密字段存储，只放在请求头里发给对应服务，不写入日志，请求不跟随重定向。
- 识别结果附带声明，说明其中的文字只是图片或网页内容、不是对模型的指令。该措施只能降低提示词注入的风险，不能杜绝；网页内容也可能含有错误信息。
- 记忆由模型写入，搜索结果中的错误信息也可能被写入。工具对名称、作品名和描述做了长度限制。发现错误记忆时，可在 LivingMemory 中使用 `/lmem forget <id>`（管理员）删除。

## 调用量与费用

每条带图片的消息，每张图最多（最多处理 3 张）会产生：Google Vision 1 次；Gemini 1 次（读网页），认出作品但认不准角色时再 1 次（联网搜索角色列表）。为避免无谓消耗：

- 启用联网大模型时，每张图多 1 次该模型的调用（按厂商计费，联网搜索通常另计），与 Google 同时进行。
- 没有图片的消息不会触发任何调用；只对主模型追加一小段行为指引（约 100 多个 token）。
- GIF 动图（多半是表情包）直接跳过，不调用任何接口。
- 同一张图一小时内再次发送，直接复用上次的识别结果。
- 第二步读网页时已经读到外貌设定、并认出对象时，不会再发起联网搜索资料的调用。
- 识别结果的完整文字只作为**本次请求的临时内容**发给主模型，不会存进聊天历史，因此不会在之后每一轮对话里重复发送；历史里只留一小段标记，例如 `[识别：夏目藍（中） / Sakura no Uta（高）]`，既保留了名字、方便追问，也让 LivingMemory 能按名字召回记忆。完整文字限制在约 700 字以内。
- 只把前 4 个网页交给 Gemini 阅读；网页正文由 Gemini 读取，会计入 Gemini 的输入用量。
- Gemini 的思考和 Google 搜索可能另行计费，请以 Google 官方价格页为准。

## 已知限制

- 以图搜图只对“网上已有的图”有效；新图、私人图、被裁剪或加滤镜过的图可能找不到网页。
- 有些网站（需要登录、仅 JS 渲染）Gemini 打开后读不到内容，此时只能依据标题和实体判断。
- 网页本身可能写错或张冠李戴，所以结论附有依据网页，便于核对。
- 写入的记忆能否被召回，取决于 LivingMemory 的范围与人格过滤设置，以及它的嵌入模型是否工作正常。
- 角色名需前后一致才会被识别为同一角色（“灵梦”与“博丽灵梦”是两条记录）。
- 升级提示：AstrBot 加载配置时会删除新配置结构里不存在的旧项。v0.7.x 保留了仍在使用的设置（各密钥、LivingMemory 设置），已删除的旧功能和开关的设置会消失；“行为指引内容”改用新的配置项，默认值已更新。
