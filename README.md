# astrbot_plugin_vision_memory

为 AstrBot 提供两项能力，需配合 [LivingMemory](https://github.com/lxfight-s-Astrbot-Plugins/astrbot_plugin_livingmemory) 使用：

1. **使用更强的模型识图**：把图片交给专门的识图模型生成文字描述，再交给主模型回复，使识图质量不受主模型自身视觉能力的限制。
2. **将已核实的角色信息写入长期记忆**：模型对图片或对话中的动漫、游戏角色、作品、表情包不确定时，先查记忆、再联网核实；核实后的结论写入 LivingMemory，之后同一角色不必重复检索。

## 功能

| 功能 | 说明 |
| --- | --- |
| 图片转述 | 使用指定的识图模型描述消息中的图片，并以文字形式附加到用户消息；可选择是否同时保留原图。 |
| 行为指引 | 向系统提示词末尾追加一段指引（不覆盖原有人设），要求模型在不确定时先查证、不得凭印象编造。 |
| 角色记忆写入 | 提供 `save_character_memory` 工具。模型核实角色后调用，插件通过 LivingMemory 外部 API 写入记忆。 |

所有模型调用均通过 AstrBot 已配置的提供商完成。长期记忆的存储、召回与总结由 LivingMemory 负责，本插件不自行存储记忆数据。

## 工作流程

```
用户消息（含图片）
   │
   ├─ 1. 识图模型生成图片描述，附加到用户消息
   │
   ├─ 2. LivingMemory 以包含描述的消息为查询，召回相关记忆
   │      （本插件 hook 优先级为 10，先于 LivingMemory 默认的 0 执行）
   │
   ├─ 3. 主模型回复。若对角色或出处不确定：
   │      查记忆 → 联网搜索核实 → 说明结论；仍无法确认时如实说明
   │
   └─ 4. 结论核实无误后，调用 save_character_memory
          → 本插件 POST 到 LivingMemory 外部 API → 之后可直接召回
```

## 运行要求

- AstrBot ≥ 4.24.2
- 已安装并配置 LivingMemory（含其所需的嵌入模型）
- 一个支持图片输入的模型提供商，用于图片转述
- 主模型及其 API 支持 Function Calling（联网搜索与记忆写入均通过工具调用实现）

## 安装与配置

### 1. 本插件配置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 图片转述（总开关） | 开启 | 关闭后插件不处理图片，原图原样传给主模型。 |
| 识图模型 | 空 | 选择用于识图的提供商。留空则不进行转述。 |
| 图片转述提示词 | 见界面 | 发送给识图模型的指令。默认要求其不确定时不要猜测角色名。 |
| 转述后移除原图 | 开启 | 开启后主模型只接收文字描述；关闭则原图与描述一并传给主模型。 |
| 单条消息最多转述的图片数 | 4 | 超出的图片跳过并在文字中注明，用于控制调用次数与费用。 |
| 单张图片转述超时（秒） | 60 | 超时按识别失败处理，不阻塞对话。 |
| 单张图片描述的最大字数 | 800 | 超出部分截断，控制 token 消耗。 |
| 本地图片大小上限（MB） | 10 | 仅对本地文件和 base64 图片生效；远程链接图片的大小由服务商限制。 |
| 追加行为指引 | 开启 | 是否向系统提示词追加指引。 |
| 行为指引提示词 | 见界面 | 指引内容，可自行修改。 |
| LivingMemory 外部 API 地址 | `http://127.0.0.1:7801` | LivingMemory 外部 API 的地址。 |
| LivingMemory 外部 API Key | 空 | 以 `lm_` 开头、具备 write 权限的 Key。 |
| 写入的记忆范围 | `session` | `session` 写入当前会话范围；`global` 写入全局范围。 |
| 调试：输出最终用户消息 | 关闭 | 仅用于排查问题，开启后描述内容会出现在日志中。 |

### 2. AstrBot 配置

1. 清空“默认图片转述模型”（`default_image_caption_provider_id`），避免与本插件重复转述。
2. 在机器人实际使用的配置文件中开启内置 Web Search（配置 → AI → 能力）。

### 3. LivingMemory 外部 API

本插件通过 LivingMemory 外部 API（`POST /page/external/memories`）写入记忆：

1. 在 LivingMemory 中启用 `external_api.enabled`（默认监听 `127.0.0.1:7801`）。
2. 使用 `/lmem apikey` 创建具备 **write** 权限的 Key，填入本插件的“LivingMemory 外部 API Key”。

写入请求包含：

- `persona_id`：当前会话生效的人格，取法与 LivingMemory 一致（会话设置 → 对话绑定人格 → 默认人格）。
- `scope`：默认为当前会话范围。若 LivingMemory 的 `memory_scope_mode` 为 `global`，请将“写入的记忆范围”设为 `global`。
- `idempotency_key`：由范围、人格、角色名和作品名生成，同一角色重复保存不会产生重复记忆。

## 行为指引

默认指引的要点：

1. 只要对角色名或出处**不能完全确定**（包括“好像见过”“有点眼熟”），就不得凭印象回答。
2. 先调用 `recall_long_term_memory` 查询长期记忆。
3. 查无结果或仍不确定，联网搜索一次核实。
4. 回复中明确给出角色名和作品名；搜索后仍无法确认的，如实说明，不得编造。
5. 仅在核实无误后调用 `save_character_memory`。

对完全确定的内容无需搜索，也不应对每个问题都搜索。

## 错误处理

插件的设计原则是不影响正常对话，任何失败都会降级并写入日志：

| 情形 | 处理 |
| --- | --- |
| 识图超时、接口报错或返回空内容 | 该图片标注“识别失败” |
| 图片数量或大小超限 | 该图片标注“已跳过” |
| 未配置外部 API 地址或 Key | 不写入，向模型返回原因 |
| 外部 API 未启用、Key 无效、无权限、被限流、无法连接或超时 | 不写入，向模型返回具体原因 |

## 隐私与安全

- 图片会被发送到所选识图模型的服务商。若使用免费额度，服务商可能将数据用于产品改进，请自行评估。
- 外部 API Key 以保密字段存储，不会写入日志。Key 会随请求发送到“外部 API 地址”，请使用本机地址；请求不会跟随重定向，Key 不会被转发到其他主机。
- 图片描述附带声明，说明其中出现的文字只是图片内容、不是对模型的指令。该措施只能降低提示词注入的风险，不能完全杜绝。
- 记忆由模型写入。搜索结果中的错误信息或恶意内容也可能被写入。工具对名称、作品名和描述做了长度限制，并要求名称与作品名非空。发现错误记忆时，可在 LivingMemory 中使用 `/lmem forget <id>`（管理员）删除。

## 已知限制

- 写入的记忆能否被召回，取决于 LivingMemory 的范围与人格过滤设置。
- 本插件依赖 LivingMemory 外部 API 的接口格式，其版本变更后可能需要适配。
- 远程图片链接的大小无法在转述前检查，由识图服务商限制。
